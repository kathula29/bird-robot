# \# Contribution Instructions

# 

# 1\. Start from the agreed current project branch and create a separate

# &#x20;  branch for each task. Use a clear name, such as docs/repository-setup.

# 

# 2\. Make only the changes relevant to that task. Keep files in their

# &#x20;  appropriate folders and preserve editable source files.

# 

# 3\. Check the changed files before committing. Do not include passwords,

# &#x20;  access tokens, private keys or other credentials.

# 

# 4\. Write a clear commit summary describing what changed, then push

# &#x20;  or publish the branch to GitHub.

# 

# 5\. Open a pull request explaining:

# &#x20;  - What changed.

# &#x20;  - The related Zoho task.

# &#x20;  - Checks performed and evidence links.

# &#x20;  - Pending issues or blockers.

# 

# 6\. Request review from the designated reviewer. Merge into main only

# &#x20;  after approval. If approval is pending, leave the pull request open.

# 

# 7\. Record actual work, evidence, actual time spent, blockers and next

# &#x20;  steps in the daily build log.

# 

# 8\. Update revision records when hardware, software or CAD versions

# &#x20;  change. Do not record planned checks as completed tests.
